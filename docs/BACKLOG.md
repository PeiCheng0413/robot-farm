# 浮葉農場｜遊戲設計決策與待辦

2026-10-15 經逐題拷問定案；同日依實測修訂（田改為「形狀 × 類型」、函式、且／或）。已定案的項目不重開，除非使用者自己推翻。

## 核心概念

玩法參考 Swift Playgrounds：學生用 Blockly 積木寫腳本控制機器人種田，學習運算思維。
每塊田是一個固定的不規則形狀（像益智魔珠的零件），形狀本身就是一道程式題目。

## 已定案

**田塊與盤面**
- 田塊由多個方格組成，形狀固定。每塊田綁一份腳本，各自是一道獨立題目。
- 排列模式像益智魔珠：把田塊塞進盤面。排列只受空間限制，不影響腳本，相鄰田塊不連通。
- 田塊和盤面格子都用金錢解鎖。田塊是題目和收益的來源；盤面是空間限制。
- 擴地（2026-10-15）：一格一格買，只能買上下左右緊鄰已開放格子的格子，越買越貴（config.js LAND_PRICE）。
- 買田（2026-10-15）：價格＝形狀底價 × 類型倍數。買下先進倉庫，排列模式從倉庫拖到盤面；盤面上的田也能拖回倉庫。倉庫裡的田不生長、機器人不去。
- 賣田：退回一半買價，田、作物、腳本一起消失（形狀種類之後還會增加，不保留腳本）。盤面上至少要留一塊田。
- 排列：田塊可旋轉 90°、不可翻面（旋轉後腳本照樣能用），拖曳吸附格子。
- **田＝形狀 × 類型**（2026-10-15 修訂）。形狀（直線、L、T、U…）只決定走位題目；類型只決定輔助規則。任何形狀都能搭任何類型。
- **類型解鎖後固定，不能升級**：規則單純，也避免升級後舊腳本出錯。想換類型就把田賣回，再買新的（v0.4）。
- 四種類型，一級拿掉一項輔助，越難的類型能種越高級的作物：
  - 新手：不扣 Token、系統自動選播種／採收腳本、土壤不會乾。種 1 級作物。
  - 進階：扣 Token；其餘同新手。種到 2 級。
  - 高級：扣 Token、土壤會乾；系統自動選播種／採收／澆水腳本。種到 3 級。
  - 專家：一份腳本全部自己判斷，含守門（沒事做就離開）。種到 4 級。
- 數值都在 `game/config.js` 的 `PLOT_TYPES` 與 `CROPS`。原因：全手動的專家田對國中生太難，要先在新手田練走位，再一級一級學。
- 之後（v0.5）加入排列加成，例如同種相鄰增產。

**機器人與排程**
- 機器人是可購買的資源，一開始一隻。
- 機器人依固定順序輪流服務各塊田，盡量讓每塊田都被執行到。排程必須是確定性的，同樣的狀態和時間一定得到同樣結果。

**腳本執行**
- 動作只有直角轉彎（相對方向的左轉、右轉）。預定動作：前進、左轉、右轉、跨越障礙、播種、澆水、採收、除草、除蟲、施肥，之後會繼續擴充。積木和田格狀態都要做成「新增一筆定義就能用」。
- 專家田：一份腳本，一次執行是一輪完整作業，要用條件判斷，例如「如果成熟就採收」。
- 新手／進階／高級田：分階段腳本，由系統依作物狀態決定跑哪一份（優先順序：採收 > 播種 > 澆水）。上一輪跑過的腳本下次往後排，避免某份腳本霸佔（例如留一格空地不種時，播種腳本會一直被派、澆水永遠輪不到）。澆水只看還在長、而且乾裂的作物，空地乾掉不派。
- 條件積木有「且」「或」「不是」。「這塊田…」檢查整塊田任一格，「腳下…」只檢查機器人所在那格，兩者容易混淆，介面要講清楚。
- 函式（2026-10-15）：先做「每份腳本各自定義」，定義與內容計入積木數，呼叫不扣 Token，暫不支援參數。全農場共用函式庫等最難版本定案後再評估。
- 執行時不使用 Blockly：積木存成 JSON 指令樹，由自己寫的逐步直譯器執行。全遊戲共用一個節拍器。畫面外的田只運算、不畫動畫。

**Token 與金錢**
- 兩種資源：Token、金錢。金錢可兌換 Token。
- Token 是全農場共用的總額。
- 動作積木每執行一次扣 Token；控制積木（重複、如果）不扣。轉彎也不扣（2026-10-15）：只有前進、播種、澆水、採收扣，難走的形狀才不會因為多轉彎而比直線田不划算。
- 每塊田的腳本有積木數上限，可花錢升級。迴圈的價值在於容量，條件判斷的價值在於避免白做。
- 新手田永遠不扣 Token，當作保底收入，但只能種 1 級作物。
- 扣 Token 的田執行到一半 Token 用完，那塊田就當機，並卡住機器人，直到玩家手動重置。重置免費，只清當機狀態，田的作物與土壤狀態保留。
- 需要「Token 剩餘量」感測積木與「離開這塊田」流程積木，讓學生自己寫防呆判斷，例如「如果 Token 小於 20 就離開」。

**收益與時間**
- 線上與離線收益用同一套模擬程式；離線時快轉，不畫畫面。離線時間設上限。
- 每塊田顯示效率統計：每輪花幾個 Token、賺多少錢、多久，也就是每分鐘淨賺多少。
- 生長時間：前期作物和新手田以分鐘計，配合課堂上的快速回饋；後期高價作物拉長到幾十分鐘甚至幾小時。數值寫成設定表，不寫死在程式裡。

**作物圖鑑**
- 第一次收成點亮條目，內含作物圖、遊戲數值、一小段真實農業知識。
- 累積收成次數達到里程碑時給小加成，例如售價加 5%。
- 知識內容由使用者用 NotebookLM 整理後匯入，Claude 負責定 JSON 格式。

**技術架構**
- 遊戲本體是 `game.html` 加上 `game/`，跟素材試驗室（`index.html`、`app.js`）分開。
- Blockly 放進 `vendor/blockly/`，固定版本，不依賴 CDN，校內 NAS 也能離線使用。零 node 依賴。
- 遊戲內動畫由 Claude 依 `manifest.json` 與 `alignment.js` 的數據播放。動畫規則必須寫在數據裡，由 ChatGPT 維護（見 `AGENTS.md`）。
- 存檔使用瀏覽器的 localStorage。

## 明確不做

- 相鄰田塊連通、讓機器人跨田移動
- 圖鑑科技樹，也就是用圖鑑解鎖作物
- 「等待」積木，也就是機器人留在田裡等收成
- Token 自然回復
- 當機重置收費
- 田的類型升級（改成賣回再買）
- 每塊田的冷卻時間：沒事做就白走扣 Token 是要學生學會守門，不替學生擋掉
- 從 CDN 載入 Blockly
- 自己寫積木編輯器
- 遊戲畫面直接引用或改寫 `app.js`
